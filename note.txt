==================================================
GOAL
====

The Intent Classifier receives a user's natural-language Rewards question and determines:

1. What the user is asking.
2. Which route should handle the request:

   * STATIC
   * DYNAMIC
   * HP_PLUS
   * UNKNOWN
3. Which data source is required:

   * KNOWLEDGE_BASE
   * REWARDS_GRAPHQL
   * HP_PLUS
   * NONE
4. If the request is dynamic, identify the appropriate GraphQL query from the supplied READ-ONLY GraphQL schema.
5. Dynamically determine the required GraphQL input variables based on the user's question and available schema.
6. Dynamically determine the response fields required to answer the user's question.
7. Generate the GraphQL query and variables using ONLY fields, arguments, input types, enums and operations that actually exist in the supplied GraphQL schema.
8. Never generate or use GraphQL mutations.
9. Never invent GraphQL fields, arguments, input parameters, enum values, or query names.
10. If the requested information cannot be obtained from the available schema/data sources, return a controlled UNKNOWN/UNSUPPORTED result rather than inventing anything.

The objective is to minimize hard-coded business-specific routing logic in Java. The LLM should use the supplied schema and intent examples to dynamically determine the appropriate read query, variables, filters and response fields.

IMPORTANT ARCHITECTURAL PRINCIPLE
=================================

Do NOT hard-code every possible natural-language variation into Java.

For example, do not create separate Java intents for:

* GET_AVAILABLE_ACTIVITIES
* GET_COMPLETED_ACTIVITIES
* GET_EXPIRED_ACTIVITIES
* GET_ACTIVITIES_NEXT_TWO_WEEKS
* GET_ACTIVITIES_THIS_MONTH
* GET_ACTIVITIES_NEXT_MONTH

Instead use broad meaningful intents and let the LLM extract parameters.

Example:

User:
"Do I have any activities I need to complete in the next two weeks?"

Possible classification:

intent = REWARDS_ACTIVITIES
route = DYNAMIC
dataSource = REWARDS_GRAPHQL

Then dynamically determine:

* activity status/filter
* date range
* appropriate query
* variables
* response fields

Use the current date supplied to the prompt when resolving relative dates such as:

* today
* tomorrow
* this week
* next week
* next two weeks
* this month
* next month

Do not hard-code those date combinations into Java.

GRAPHQL SCHEMA
==============

Use the existing rewards-service-graphql source/schema as the source of truth.
