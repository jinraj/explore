Fulfillment Source – Rule Group Design Discussion
1. Understanding the existing rule groups
Currently, rule_attribute_catalog contains two rule groups: ASSIGNMENT and FULFILLMENT.
Rule group	Purpose	Examples
ASSIGNMENT	Defines conditions to determine whether an activity should be assigned to a member.	Member group, frequency, member age, member gender
FULFILLMENT	Defines requirements that a member must complete after an activity is assigned.	Reading, claims proof, self-attestation

The distinction is clear:
1. Assignment attributes determine who gets the activity and when.
2. Fulfillment attributes determine what the member must complete.
3. Fulfillment source identifies which system or channel submits the fulfillment.
The third concept is different from the first two.
2. Where should the fulfillment source belong?
The fulfillment source does not fit perfectly into either of the existing groups. Let's look at why.
Option A: ASSIGNMENT group
Not recommended
Assignment rules determine whether an activity should be assigned to a member.

Examples:
- Member age
- Member gender
- Member group
- Frequency
A source does not determine whether a member is eligible for an activity or whether an activity should be assigned.

Therefore, it does not make sense to classify fulfillment source under ASSIGNMENT.
Option B: FULFILLMENT group
Possible, but not an exact fit
Fulfillment rules define the requirements that a member must complete.

Examples:
- Reading
- Claims proof
- Self-attestation
A fulfillment source does not represent an additional task or requirement that the member must complete. Instead, it identifies where the completion request originates.

However, source is closely associated with fulfillment because it is used to validate whether a particular fulfillment can be accepted.

For example:
- Reading can be fulfilled through ATHENA or CRM.
- Self-attestation can be fulfilled through HBP.
- Claims proof can be fulfilled through CRM or PSP.
Therefore, source is related to fulfillment, but it is not itself a fulfillment requirement.
Option C: Introduce a new SOURCE group
Recommended for the current implementation
Add a third group, SOURCE, to the existing rule_attribute_catalog.

This keeps the existing groups unchanged and gives source its own classification.
Rule group	Purpose	Examples
ASSIGNMENT	Conditions for activity assignment	Member age, gender, frequency, member group
FULFILLMENT	Requirements to be completed	Reading, claims proof, self-attestation
SOURCE	Originating systems or channels for fulfillment submissions	HBP, CRM, PSP, ATHENA

This is a practical approach for the current application without introducing another database table.
